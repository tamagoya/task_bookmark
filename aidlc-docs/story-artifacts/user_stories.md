# User Stories - タスクブックマーク Chrome 拡張

## プロジェクト概要
論文「タスクブックマーク: 計算機上の仕事状態の保存と復元機能の提案」に基づき、ブラウザの作業状態をGoogle Calendarに保存・復元するChrome拡張機能を開発します。

## ターゲットユーザー
- ビジネスパーソン（営業、マーケティング、プロジェクトマネージャーなど）
- ソフトウェア開発者

## 利用シーン
- 1日20個程度の仕事状態を保存（30分に1つ程度）
- 1つの仕事で平均10個のタブを開いている
- 毎日複数回、過去の仕事を復元する

---

## User Story 1: Googleアカウント認証とカレンダー初期化

**ユーザー役割**: 初回利用者（ビジネスパーソン / ソフトウェア開発者）

**機能**: 
初回起動時にGoogleアカウントで認証し、専用カレンダーを自動作成する

**ビジネス価値**: 
セキュアな認証と、ユーザーが意識せずに使えるカレンダー環境を提供することで、導入障壁を下げる

**受け入れ基準**:
- [ ] Chrome拡張機能をインストール後、初回起動時にOAuth 2.0認証フローが開始される
- [ ] Googleアカウントで正常に認証できる
- [ ] 認証後、専用カレンダー「タスクブックマーク」が自動作成される（存在しない場合）
- [ ] 既にカレンダーが存在する場合は、既存のカレンダーを使用する
- [ ] 認証状態がChrome Storageに安全に保存される
- [ ] 認証エラー時は、ユーザーフレンドリーなエラーメッセージを表示する

**優先度**: 高（MVP必須）

---

## User Story 2: 現在のタブ状態の取得と表示

**ユーザー役割**: 作業中のユーザー（ビジネスパーソン / ソフトウェア開発者）

**機能**: 
全てのChromeウィンドウで開いているタブの情報（URL、タイトル、ファビコン）を取得し、サイドパネルに表示する

**ビジネス価値**: 
保存前に内容を確認できることで、ユーザーが保存する情報を把握し、安心して保存できる。複数ウィンドウにまたがる仕事を一括で確認できる。

**受け入れ基準**:
- [ ] サイドパネルを開くと、全てのChromeウィンドウで開いているタブが一覧表示される
- [ ] 各タブについて、以下が表示される：
  - [ ] ページタイトル
  - [ ] URL（表示用に短縮可能）
  - [ ] ファビコン（視覚的な識別のため）
- [ ] タブの順序が保持される（ウィンドウ単位・同一ウィンドウ内のインデックス順）
- [ ] タブ情報の取得に失敗した場合、エラーメッセージを表示する

**優先度**: 高（MVP必須）

## User Story 3: 仕事状態の保存（メタデータ入力とカレンダー保存）

**ユーザー役割**: 作業中のユーザー（ビジネスパーソン / ソフトウェア開発者）

**機能**: 
仕事名とメモを入力し、全てのChromeウィンドウのタブ状態をGoogle Calendarにイベントとして保存する

**ビジネス価値**: 
30分に1回程度の頻繁な保存を、ブックマーク作成と同等の手軽さで実現し、タスク切り替え時の生産性を向上させる。複数ウィンドウにまたがる仕事を一括保存できる。

**受け入れ基準**:
- [ ] サイドパネルに「保存」ボタンまたはフォームが表示される
- [ ] ユーザーが以下を入力できる：
  - [ ] 仕事名（必須、カレンダーイベントのタイトルとして使用）
  - [ ] 作業メモ（任意）
- [ ] 保存対象は、全てのChromeウィンドウで開いているタブとする
- [ ] 保存実行時の時刻を終了時間として、30分前を開始時間とするイベントが作成される
- [ ] イベントの説明欄に、以下の構造化データ（JSON形式）が保存される：
  - [ ] タブ情報の配列（URL、タイトル、ファビコンURL）
  - [ ] 保存日時（ISO 8601形式）
  - [ ] メタデータ（仕事名、メモ）
  - [ ] スキーマバージョン（将来の拡張性のため）
- [ ] 保存成功時、成功メッセージを表示する
- [ ] 保存失敗時（API エラーなど）、エラーメッセージを表示する
- [ ] 保存成功後、保存した全ウィンドウのタブを自動的に閉じる（作業状態をリセットする）
- [ ] 保存成功後、新しいタブを1つだけ開いた新規ウィンドウを表示する（すぐにタスクブックマークを開いて別の仕事を再開できるようにする）
- [ ] 保存後、保存したURLリストを編集可能にする（後続のStoryで実装）

**優先度**: 高（MVP必須）

**技術的注記**: 
- Google Calendar API v3を使用
- イベント説明欄のJSONは、プログラムが読み取りやすい形式（インデント付き、明確なキー名）で保存

## User Story 4: 保存済み仕事状態の一覧表示

**ユーザー役割**: 過去の仕事を再開したいユーザー（ビジネスパーソン / ソフトウェア開発者）

**機能**: 
Google Calendarから保存済みの仕事状態を取得し、サイドパネルに時系列で一覧表示する

**ビジネス価値**: 
過去の作業履歴を可視化し、どの仕事を再開するか素早く判断できる

**受け入れ基準**:
- [ ] サイドパネルに「保存済み仕事」セクションが表示される
- [ ] 専用カレンダーから過去のイベントを取得し、時系列（新しい順）で表示する
- [ ] 各仕事について、以下が表示される：
  - [ ] 仕事名（カレンダーイベントのタイトル）
  - [ ] 保存日時（開始時間と終了時間）
  - [ ] タブ数（視覚的な情報量の指標）
  - [ ] ファビコンのサムネイル（最初の数個のタブのファビコンを表示）
- [ ] 検索機能（仕事名で検索可能）
- [ ] 日付フィルタリング（今日、今週、今月など）
- [ ] データ取得中はローディングインジケーターを表示する
- [ ] 取得エラー時は、エラーメッセージと再試行ボタンを表示する

**優先度**: 高（MVP必須）

---

## User Story 5: 仕事状態の復元（タブの一括展開）

**ユーザー役割**: 過去の仕事を再開したいユーザー（ビジネスパーソン / ソフトウェア開発者）

**機能**: 
カレンダーから選択した仕事状態を復元し、記録されたタブ群を新しいウィンドウで一括展開する

**ビジネス価値**: 
過去の仕事を再開する際の手間を大幅に削減し、タスク切り替え時の生産性を向上させる

**受け入れ基準**:
- [ ] 保存済み仕事一覧から、復元したい仕事を選択できる
- [ ] 「復元」ボタンをクリックすると、新しいウィンドウが開く
- [ ] 新しいウィンドウに、記録された全てのタブが順番通りに展開される
- [ ] 各タブは、記録されたURLで開かれる
- [ ] 復元実行時の時刻を開始時間として、カレンダーイベントに記録する（メタデータとして）
- [ ] 復元元の仕事との関連性（前後関係）をメタデータとして保持する
- [ ] 復元中は、プログレスインジケーターを表示する
- [ ] 大量のタブ（20個以上）を復元する場合、段階的に読み込む（パフォーマンス対策）
- [ ] 復元失敗時（URLが無効など）は、エラーメッセージを表示し、成功したタブは開いたままにする

**優先度**: 高（MVP必須）

**技術的注記**: 
- 復元時に、元の仕事イベントのメタデータに「復元日時」と「復元元イベントID」を追加して保存
- これにより、仕事の前後関係を追跡可能にする

## User Story 6: 保存済みURLの編集

**ユーザー役割**: 保存後にURLを修正したいユーザー（ビジネスパーソン / ソフトウェア開発者）

**機能**: 
保存済みの仕事状態について、保存されているURLリストを編集できる

**ビジネス価値**: 
機密情報を含むURLを削除したり、不要なタブを除外したりすることで、データの安全性と整理性を向上させる

**受け入れ基準**:
- [ ] 保存済み仕事の詳細表示画面で、URLリストが編集可能な形式で表示される
- [ ] ユーザーが以下を実行できる：
  - [ ] 個別のURLを削除
  - [ ] URLの順序を変更（ドラッグ&ドロップ）
  - [ ] 新しいURLを追加（手動入力）
- [ ] 編集内容を保存すると、Google Calendarイベントの説明欄が更新される
- [ ] 編集内容は、構造化データの形式を維持する
- [ ] 編集履歴をメタデータとして記録する（オプション、将来の拡張）

**優先度**: 中（MVP後、早期実装推奨）

## User Story 7: 仕事の前後関係の可視化

**ユーザー役割**: 仕事の流れを把握したいユーザー（ビジネスパーソン / プロジェクトマネージャー）

**機能**: 
保存された仕事の前後関係（どの仕事から復元されたか、どの仕事に続いたか）を可視化する

**ビジネス価値**: 
仕事の引き継ぎ分析に役立ち、作業の流れを理解しやすくする

**受け入れ基準**:
- [ ] 保存済み仕事一覧または詳細画面で、前後関係が表示される
- [ ] 「この仕事から復元された仕事」のリストを表示する
- [ ] 「この仕事から復元された仕事」のリストを表示する（逆方向）
- [ ] 前後関係を視覚的に表現する（例: ツリー表示、タイムライン表示）
- [ ] 前後関係がない場合（最初の保存、または復元されていない）は、その旨を表示する

**優先度**: 中（MVP後、引き継ぎ分析の要望に対応）

**技術的注記**: 
- メタデータに「復元元イベントID」と「復元先イベントIDリスト」を保持
- これにより、仕事のチェーンを構築可能

## User Story 8: オフライン時の動作とエラーハンドリング

**ユーザー役割**: すべてのユーザー

**機能**: 
ネットワークエラーやAPI制限などのエラー状況を適切に処理し、ユーザーに分かりやすいフィードバックを提供する

**ビジネス価値**: 
信頼性の高いツールとして、ユーザーの作業を中断させない

**受け入れ基準**:
- [ ] ネットワークエラー時、リトライ機能を提供する
- [ ] Google Calendar APIのレート制限に達した場合、適切なメッセージを表示する
- [ ] 認証トークンの有効期限切れ時、自動的に再認証を促す
- [ ] すべてのエラーについて、ユーザーフレンドリーな日本語メッセージを表示する
- [ ] エラーログを適切に記録する（デバッグ用）

**優先度**: 高（信頼性のため）

---

## User Story 9: サイドパネルUIの実装とUX最適化

**ユーザー役割**: すべてのユーザー

**機能**: 
Chrome 114+のサイドパネルAPIを使用して、直感的で使いやすいUIを実装する

**ビジネス価値**: 
ブックマーク作成と同等の手軽さで操作できるUXを実現し、頻繁な使用を促進する

**受け入れ基準**:
- [ ] Chrome拡張機能のアイコンをクリックすると、サイドパネルが開く
- [ ] サイドパネル内で、以下が快適に操作できる：
  - [ ] タブ一覧の表示（スクロール可能）
  - [ ] フォーム入力（仕事名、メモ）
  - [ ] 保存済み仕事の一覧表示
  - [ ] 検索・フィルタリング
- [ ] レスポンシブデザイン（パネルサイズに応じて適切に表示）
- [ ] 操作が難しい場合は、ポップアップウィンドウへの切り替えを検討する（将来の拡張）

**優先度**: 高（MVP必須）

**技術的注記**: 
- Chrome 114+のSide Panel APIを使用
- 必要に応じて、popup.htmlへのフォールバックを実装

---

## 優先度の定義
- **高**: MVPに必須の機能
- **中**: MVP後、早期実装を推奨する機能
- **低**: 将来の拡張機能

---

## 受け入れ基準の共通要件
すべてのUser Storyについて、以下を満たす必要があります：
- エラーハンドリングが適切に実装されている
- ユーザー入力の検証が行われている
- セキュリティベストプラクティスに準拠している（OAuth、データ暗号化など）
- パフォーマンスが許容範囲内（大量のタブ処理、API呼び出しの最適化）
