# コード生成計画: RetryHandlerの拡張

## 概要

既存の`RetryHandler`を拡張して、ドメイン層の`RetryPolicy`を使用するように変更します。これにより、ビジネスルール（リトライポリシー）がドメイン層で定義され、インフラストラクチャ層はそれを使用するようになります。

## 目的

- 既存の`RetryHandler`を`RetryPolicy`を受け取るように拡張
- 後方互換性を保つ（既存のコードが動作し続ける）
- ビジネスルールをドメイン層に配置（DDD原則に準拠）

## 作業範囲

### インフラストラクチャ層
- [ ] `RetryHandler`に`RetryPolicy`を受け取るメソッドを追加
- [ ] 既存のメソッドは後方互換性のため維持
- [ ] 新しいメソッド: `executeWithRetryPolicy(operation, retryPolicy)`

### テスト
- [ ] 既存のテストが引き続き動作することを確認
- [ ] 新しいメソッドのテストを追加（TDD）

## 実装アプローチ

### 変更内容
1. `RetryHandler`に新しいメソッド`executeWithRetryPolicy`を追加
2. `RetryPolicy`からリトライ設定を取得
3. `RetryPolicy.calculateDelay()`を使用して遅延時間を計算
4. 既存の`executeWithRetry`メソッドは変更しない（後方互換性）
