# 測定基準 (Measurement Criteria) - タスクブックマーク Chrome 拡張

## 概要
本ドキュメントは、タスクブックマークChrome拡張機能の成功を測定するための定量的・定性的基準を定義します。ビジネス意図（タスク切り替え時の生産性向上、過去の作業履歴の可視化）にトレース可能な測定基準を設定します。

---

## 測定基準の原則

### SMART基準
すべての測定基準は、以下のSMART原則に準拠します：
- **Specific（具体的）**: 明確で具体的な指標
- **Measurable（測定可能）**: 定量的に測定可能
- **Achievable（達成可能）**: 現実的に達成可能
- **Relevant（関連性）**: ビジネス意図と関連している
- **Time-bound（期限）**: 明確な期限がある

## 1. ビジネス成果の測定基準

### 1.1 タスク切り替え時の生産性向上

#### 指標1.1.1: 作業再開時間の短縮
**目標**: 作業再開時間を50%以上短縮する

**測定方法**:
- **ベースライン**: ユーザーが手作業でタブを開き直す時間（平均10タブで約2分）
- **目標値**: 復元機能を使用した場合、10タブを5秒以内で復元（目標: 2分 → 5秒、約96%短縮）
- **測定期間**: リリース後3ヶ月間
- **測定頻度**: 週次

**データ収集方法**:
- 復元操作の実行時間をログに記録
- ユーザーアンケート（作業再開時間の主観的評価）

**成功基準**:
- [ ] 10タブの復元時間が5秒以内（NFR-001）
- [ ] ユーザーの80%以上が「作業再開時間が短縮された」と回答

---

#### 指標1.1.2: タスク切り替え頻度の増加
**目標**: ユーザーがより頻繁にタスクを切り替えられるようになる

**測定方法**:
- **ベースライン**: ユーザーが1日に保存する仕事状態の数
- **目標値**: 1日あたり平均15回以上の保存（想定: 20回）
- **測定期間**: リリース後3ヶ月間
- **測定頻度**: 週次

**データ収集方法**:
- 保存操作のログを記録（匿名化）
- ユーザーごとの1日あたりの保存回数を集計

**成功基準**:
- [ ] アクティブユーザーの50%以上が、1日あたり10回以上保存
- [ ] 1日あたりの平均保存回数が15回以上

---

### 1.2 過去の作業履歴の可視化

#### 指標1.2.1: カレンダー上の作業履歴の活用
**目標**: ユーザーがカレンダー上で作業履歴を確認・活用する

**測定方法**:
- **ベースライン**: 保存済み仕事の閲覧回数
- **目標値**: アクティブユーザーの70%以上が、週に1回以上保存済み仕事を閲覧
- **測定期間**: リリース後3ヶ月間
- **測定頻度**: 週次

**データ収集方法**:
- 保存済み仕事一覧の表示回数をログに記録（匿名化）
- 復元操作の回数を記録

**成功基準**:
- [ ] アクティブユーザーの70%以上が、週に1回以上保存済み仕事を閲覧
- [ ] 週に1回以上復元操作を実行するユーザーが50%以上

---

#### 指標1.2.2: 仕事の前後関係の活用
**目標**: ユーザーが仕事の前後関係を活用して作業の流れを理解する

**測定方法**:
- **ベースライン**: 復元関係が記録された仕事の割合
- **目標値**: 保存された仕事の30%以上が、他の仕事から復元されたもの
- **測定期間**: リリース後3ヶ月間
- **測定頻度**: 月次

**データ収集方法**:
- 復元関係のメタデータを分析
- 仕事のチェーン（前後関係）の長さを測定

**成功基準**:
- [ ] 保存された仕事の30%以上が、復元関係を持つ
- [ ] 平均的な仕事チェーンの長さが3以上

## 3. ユーザー満足度の測定基準

### 3.1 ユーザー満足度スコア

#### 指標3.1.1: Net Promoter Score (NPS)
**目標**: NPSが50以上

**測定方法**:
- **質問**: 「この拡張機能を友人や同僚に薦める可能性はどの程度ですか？」（0-10点）
- **測定期間**: リリース後1ヶ月、3ヶ月、6ヶ月
- **測定頻度**: 月次

**データ収集方法**:
- ユーザーアンケート（Chrome Web Storeのレビュー、または拡張機能内のアンケート）

**成功基準**:
- [ ] NPSが50以上
- [ ] プロモーター（9-10点）の割合が50%以上

---

#### 指標3.1.2: ユーザー満足度スコア
**目標**: ユーザー満足度スコアが4.0/5.0以上

**測定方法**:
- **質問**: 「この拡張機能の全体的な満足度はどの程度ですか？」（1-5点）
- **測定期間**: リリース後1ヶ月、3ヶ月、6ヶ月
- **測定頻度**: 月次

**データ収集方法**:
- ユーザーアンケート

**成功基準**:
- [ ] ユーザー満足度スコアが4.0/5.0以上
- [ ] 4点以上を付けたユーザーが80%以上

---

### 3.2 ユーザーフィードバック

#### 指標3.2.1: 肯定的なフィードバックの割合
**目標**: 肯定的なフィードバック（4-5点）が80%以上

**測定方法**:
- **測定期間**: リリース後継続的に
- **測定頻度**: 週次

**データ収集方法**:
- Chrome Web Storeのレビュー
- 拡張機能内のフィードバックフォーム

**成功基準**:
- [ ] 肯定的なフィードバック（4-5点）が80%以上
- [ ] 否定的なフィードバック（1-2点）が10%以下

## 4. 技術的パフォーマンスの測定基準

### 4.1 パフォーマンス指標

#### 指標4.1.1: 保存操作のレスポンス時間
**目標**: 保存操作が2秒以内で完了する（NFR-001）。保存対象は全Chromeウィンドウのタブのため、複数ウィンドウ・タブ数が多い場合でも目標を満たすことを目指す。

**測定方法**:
- **測定期間**: リリース後継続的に
- **測定頻度**: 日次

**データ収集方法**:
- 保存操作の実行時間をログに記録
- パーセンタイル（p50, p95, p99）を計算

**成功基準**:
- [ ] 50%の保存操作が2秒以内で完了（p50 ≤ 2秒）
- [ ] 95%の保存操作が3秒以内で完了（p95 ≤ 3秒）

---

#### 指標4.1.2: 復元操作のレスポンス時間
**目標**: 10タブの復元が5秒以内で完了する（NFR-001）

**測定方法**:
- **測定期間**: リリース後継続的に
- **測定頻度**: 日次

**データ収集方法**:
- 復元操作の実行時間をログに記録
- タブ数ごとの平均復元時間を計算

**成功基準**:
- [ ] 10タブの復元が5秒以内で完了（p50 ≤ 5秒）
- [ ] 20タブの復元が10秒以内で完了（p50 ≤ 10秒）

---

#### 指標4.1.3: 一覧取得のレスポンス時間
**目標**: 過去30日分の一覧取得が3秒以内で完了する（NFR-001）

**測定方法**:
- **測定期間**: リリース後継続的に
- **測定頻度**: 日次

**データ収集方法**:
- 一覧取得操作の実行時間をログに記録

**成功基準**:
- [ ] 過去30日分の一覧取得が3秒以内で完了（p50 ≤ 3秒）

---

### 4.2 エラー率

#### 指標4.2.1: 保存操作のエラー率
**目標**: 保存操作のエラー率が5%以下

**測定方法**:
- **測定期間**: リリース後継続的に
- **測定頻度**: 日次

**データ収集方法**:
- 保存操作の成功/失敗をログに記録
- エラー率を計算（エラー数 / 総リクエスト数）

**成功基準**:
- [ ] 保存操作のエラー率が5%以下
- [ ] 認証エラー以外のエラー率が2%以下

---

#### 指標4.2.2: 復元操作のエラー率
**目標**: 復元操作のエラー率が10%以下（無効なURLなどは許容）

**測定方法**:
- **測定期間**: リリース後継続的に
- **測定頻度**: 日次

**データ収集方法**:
- 復元操作の成功/失敗をログに記録
- 部分的な復元（一部のタブが失敗）も記録

**成功基準**:
- [ ] 復元操作の完全失敗率が10%以下
- [ ] 部分的な復元（一部のタブが失敗）を含めたエラー率が20%以下

## 6. 測定の実施計画

### 6.1 データ収集方法
- **ログ記録**: 主要な操作（保存、復元、一覧取得）の実行時間とエラーを記録
- **ユーザーアンケート**: リリース後1ヶ月、3ヶ月、6ヶ月に実施
- **Chrome Web Storeレビュー**: 継続的に監視

### 6.2 プライバシー配慮
- すべてのログは匿名化（個人を特定できる情報を含まない）
- ユーザーの同意を得てからデータを収集
- GDPRなどのデータ保護法に準拠

### 6.3 測定レポート
- **週次レポート**: 技術的パフォーマンス指標
- **月次レポート**: ビジネス成果指標、ユーザー満足度
- **四半期レポート**: 包括的な分析と改善提案

## 7. 成功の定義

### MVP成功基準（リリース後3ヶ月）
以下の基準をすべて満たす場合、MVPは成功とみなします：

- [ ] **機能使用**: アクティブユーザーの80%以上が保存・復元機能を使用
- [ ] **パフォーマンス**: 保存が2秒以内、復元が5秒以内（p50）
- [ ] **エラー率**: 保存エラー率が5%以下、復元エラー率が10%以下
- [ ] **ユーザー満足度**: NPSが50以上、ユーザー満足度スコアが4.0/5.0以上
- [ ] **リテンション**: 4週間後のリテンション率が30%以上

### 長期成功基準（リリース後6ヶ月）
- [ ] **ビジネス成果**: 作業再開時間が50%以上短縮（ユーザーアンケート）
- [ ] **採用**: 週次アクティブユーザーが継続的に増加
- [ ] **リテンション**: 12週間後のリテンション率が20%以上
