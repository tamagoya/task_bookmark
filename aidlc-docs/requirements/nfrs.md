# 非機能要件 (NFRs) - タスクブックマーク Chrome 拡張

## 概要
本ドキュメントは、タスクブックマークChrome拡張機能の非機能要件を定義します。機能要件（User Stories）を実現するための技術的制約、品質基準、運用要件を明確にします。

---

## 1. パフォーマンス要件

### 1.1 レスポンス時間
- **タブ情報の取得**: 現在のウィンドウのタブ情報（最大20タブ）を取得する時間は **500ms以内**
- **カレンダーイベントの保存**: Google Calendar APIへの保存リクエスト完了まで **2秒以内**
- **保存済み仕事の一覧取得**: 過去30日分のイベント（最大600件）を取得する時間は **3秒以内**
- **タブの復元**: 10個のタブを新しいウィンドウで開く時間は **5秒以内**（ネットワーク速度に依存）

**測定方法**: 
- Chrome DevToolsのPerformanceタブで計測
- 各操作の開始から完了までの時間をログに記録

### 1.2 スループット
- **同時保存リクエスト**: ユーザーが連続して保存ボタンを押した場合、前のリクエストが完了するまで次のリクエストをキューイングする
- **API呼び出し頻度**: Google Calendar APIのレート制限（1秒あたり100リクエスト）を超えないように制御

### 1.3 リソース使用量
- **メモリ使用量**: 拡張機能のメモリ使用量は **50MB以内**（通常時）
- **CPU使用率**: バックグラウンド処理時のCPU使用率は **5%以内**（アイドル時）
- **ストレージ**: Chrome Storage APIの使用量は最小限に（認証トークン、設定のみ）

## 2. セキュリティ要件

### 2.1 認証と認可
- **OAuth 2.0準拠**: Google Identity APIを使用し、OAuth 2.0のベストプラクティスに準拠
- **トークン管理**: 
  - アクセストークンはChrome Storage API（`chrome.storage.local`）に暗号化して保存
  - トークンの有効期限を監視し、期限切れ前に自動更新
  - トークンは最小限のスコープ（`https://www.googleapis.com/auth/calendar`）のみを要求
- **認証状態の検証**: 各API呼び出し前に認証状態を確認し、無効な場合は再認証を促す

### 2.2 データ保護
- **機密情報の取り扱い**: 
  - URLに機密情報（認証トークン、セッションIDなど）が含まれる可能性があることをユーザーに警告
  - 保存後にURLを編集可能にする機能を提供（User Story 6）
- **データ暗号化**: 
  - ローカルストレージに保存する認証情報は暗号化（Chrome Storage APIの機能を利用）
  - ネットワーク通信はHTTPS経由（Google Calendar APIは自動的にHTTPS）
- **データの最小化**: 必要最小限の情報のみを保存（URL、タイトル、ファビコン、メタデータ）

### 2.3 コンテンツセキュリティポリシー（CSP）
- **Manifest V3準拠**: Content Security Policyに準拠し、インラインスクリプトや`eval()`を使用しない
- **外部リソース**: 信頼できるドメイン（`*.googleapis.com`）からのみリソースを読み込む

### 2.4 プライバシー
- **データの所有権**: すべてのデータはユーザーのGoogle Calendarに保存され、拡張機能開発者はアクセスできない
- **データの削除**: ユーザーが拡張機能をアンインストールしても、カレンダーデータは残る（ユーザーが手動で削除可能）
- **ログと分析**: エラーログのみを記録し、個人を特定できる情報（URL、タイトルなど）は含めない

## 3. 可用性要件

### 3.1 可用性目標
- **目標可用性**: 99.5%（月間ダウンタイム約3.6時間）
- **主要な障害要因**: 
  - Google Calendar APIの障害
  - ネットワーク接続の問題
  - Chrome拡張機能のバグ

### 3.2 エラーハンドリング
- **ネットワークエラー**: 
  - リトライ機能を実装（最大3回、指数バックオフ）
  - ユーザーに分かりやすいエラーメッセージを表示
- **APIエラー**: 
  - Google Calendar APIのエラーレスポンスを適切に処理
  - レート制限エラー（429）の場合は、リトライ前に待機時間を設ける
- **認証エラー**: 
  - トークンの有効期限切れ時は、自動的に再認証フローを開始
  - 認証拒否時は、ユーザーに理由を説明

### 3.3 グレースフルデグラデーション
- **オフライン時**: 
  - タブ情報の取得は可能（ローカル操作）
  - カレンダーへの保存は、オンライン復帰後にキューイング（将来の拡張）
- **API制限到達時**: 
  - ユーザーに制限到達を通知
  - 一定時間待機後に再試行を促す

## 4. 保守性要件

### 4.1 コード品質
- **テストカバレッジ**: 80%以上（ユニットテスト、統合テスト）
- **コードスタイル**: 
  - TypeScriptを使用（型安全性の確保）
  - ESLint、Prettierによるコードフォーマット
  - イミュータブルパターンの使用（既存のコーディングスタイルガイドに準拠）
- **ドキュメント**: 
  - すべての公開APIにJSDocコメントを付与
  - アーキテクチャ決定をADR（Architecture Decision Records）として記録

### 4.2 モジュール化
- **高凝集・低結合**: 
  - 機能ごとに独立したモジュールに分割
  - 各モジュールは単一責任の原則に従う
- **依存関係の管理**: 
  - 外部ライブラリの使用を最小限に
  - 依存関係のバージョンを固定（package-lock.json）

### 4.3 拡張性
- **スキーマバージョニング**: 
  - カレンダーイベントのJSONスキーマにバージョン番号を含める
  - 将来のスキーマ変更に対応できるマイグレーション機能（将来の拡張）
- **プラグインアーキテクチャ**: 
  - 将来的に他のカレンダーサービス（Outlook、Apple Calendarなど）への対応を考慮

### 4.4 ログとモニタリング
- **エラーログ**: 
  - すべてのエラーを`console.error`で記録
  - エラーの種類、発生時刻、コンテキスト情報を含める
- **パフォーマンスログ**: 
  - 主要な操作（保存、復元、一覧取得）の実行時間を記録
  - パフォーマンスの劣化を早期に検知

## 5. 互換性要件

### 5.1 ブラウザ互換性
- **Chromeバージョン**: Chrome 120以上（最新版のみ）
- **Manifest V3**: Manifest V3の仕様に完全準拠
- **API互換性**: 
  - Chrome Extension API（`chrome.tabs`, `chrome.windows`, `chrome.storage`など）
  - Chrome Identity API（OAuth認証）
  - Side Panel API（Chrome 114+）

### 5.2 プラットフォーム互換性
- **OS**: Windows、macOS、Linux（ChromeがサポートするすべてのOS）
- **アーキテクチャ**: x86_64、ARM64（Chromeがサポートするアーキテクチャ）

---

## 6. ユーザビリティ要件

### 6.1 アクセシビリティ
- **キーボード操作**: すべての主要機能をキーボードのみで操作可能
- **スクリーンリーダー**: ARIAラベルを適切に設定し、スクリーンリーダーに対応
- **色のコントラスト**: WCAG 2.1 Level AA基準に準拠（コントラスト比4.5:1以上）

### 6.2 国際化（i18n）
- **初期リリース**: 日本語のみサポート
- **将来の拡張**: 多言語対応のためのi18nフレームワークを考慮した設計

### 6.3 UX要件
- **操作の手軽さ**: ブックマーク作成と同等の手軽さで保存できる（RFP要件）
- **視覚的フィードバック**: 
  - 保存中、復元中はローディングインジケーターを表示
  - 成功・失敗時に明確なメッセージを表示
- **エラーメッセージ**: 技術的なエラーコードではなく、ユーザーが理解できる日本語メッセージを表示

---

## 7. 運用要件

### 7.1 デプロイメント
- **配布方法**: Chrome Web Store経由で配布
- **バージョン管理**: セマンティックバージョニング（Semantic Versioning）に準拠
- **更新頻度**: 必要に応じて（バグ修正、新機能追加）

### 7.2 監視とアラート
- **エラー率**: エラー発生率が5%を超えた場合、開発者に通知（将来の拡張）
- **パフォーマンス劣化**: 平均レスポンス時間が基準値の2倍を超えた場合、開発者に通知（将来の拡張）

### 7.3 バックアップと復旧
- **データの永続化**: すべてのデータはGoogle Calendarに保存されるため、Googleのバックアップ機能に依存
- **設定の復旧**: 拡張機能の設定（認証情報など）はChrome Sync経由で同期可能（Chromeの機能）

---

## 8. コンプライアンス要件

### 8.1 データ保護法
- **GDPR準拠**: ユーザーデータの処理について、GDPRの原則に準拠
- **個人情報保護**: 個人を特定できる情報の取り扱いについて、適切な保護措置を講じる

### 8.2 Chrome Web Storeポリシー
- **プライバシーポリシー**: Chrome Web Storeの要件に従い、プライバシーポリシーを公開
- **利用規約**: 拡張機能の利用規約を明確に定義

## 測定と検証

### 測定方法
- **パフォーマンス**: Chrome DevTools、Performance APIを使用
- **セキュリティ**: セキュリティ監査ツール（OWASP ZAPなど）を使用
- **可用性**: エラーログの分析、ユーザーフィードバック

### 検証基準
- すべてのNFRsについて、実装前に設計レビューを実施
- 実装後、各NFRsの達成状況を検証
- 継続的なモニタリングと改善
