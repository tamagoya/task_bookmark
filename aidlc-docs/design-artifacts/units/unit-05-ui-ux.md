# Unit 5: UI/UX実装

## 概要
Chrome拡張機能のユーザーインターフェースを実装するUnitです。サイドパネル（Chrome 114+）を主要UIとして、直感的で使いやすいインターフェースを提供します。

## 責任範囲
- サイドパネルUIの実装
- フォーム入力（仕事名、メモ）
- タブ一覧の表示
- 保存済み仕事一覧の表示
- 検索・フィルタリング機能
- プログレスインジケーター
- エラーメッセージの表示
- アクセシビリティ対応

## 関連User Stories
- **US-2**: 現在のタブ状態の取得と表示（UI部分）
- **US-3**: 仕事状態の保存（フォーム入力UI）
- **US-4**: 保存済み仕事状態の一覧表示
- **US-5**: 仕事状態の復元（復元ボタンUI）
- **US-6**: 保存済みURLの編集（編集UI）
- **US-7**: 仕事の前後関係の可視化（可視化UI）
- **US-8**: オフライン時の動作とエラーハンドリング（エラー表示UI）
- **US-9**: サイドパネルUIの実装とUX最適化

## 入力
- ユーザーの操作（クリック、入力、選択）
- 各Unitからのデータ（タブ情報、保存済み仕事、エラー情報）

## 出力
- ユーザー操作のイベント（保存、復元、編集など）
- UI状態の更新

## 主要コンポーネント

### 1. Side Panel Component
**責任**: サイドパネルのメインコンテナ

**主要機能**:
- サイドパネルの表示制御
- ルーティング（タブ一覧、保存済み仕事一覧、設定など）
- レイアウト管理

**依存関係**:
- Chrome Side Panel API (`chrome.sidePanel`)

### 2. Tab List Component
**責任**: 現在のタブ一覧の表示

**主要機能**:
- タブ一覧の表示（タイトル、URL、ファビコン）
- タブの順序表示
- スクロール可能なリスト

**依存関係**:
- Unit 2 (タブキャプチャ): タブ情報の取得

### 3. Save Form Component
**責任**: 仕事状態保存のフォーム

**主要機能**:
- 仕事名の入力（必須）
- メモの入力（任意）
- 保存ボタン
- バリデーション

**依存関係**:
- Unit 3 (Calendar API): 保存処理

### 4. Work State List Component
**責任**: 保存済み仕事一覧の表示

**主要機能**:
- 時系列での一覧表示
- 検索機能（仕事名で検索）
- 日付フィルタリング（今日、今週、今月）
- 復元ボタン
- 詳細表示ボタン

**依存関係**:
- Unit 3 (Calendar API): 保存済み仕事の取得

### 5. Work State Detail Component
**責任**: 保存済み仕事の詳細表示と編集

**主要機能**:
- 仕事の詳細情報表示
- URLリストの表示と編集
- 前後関係の表示
- 保存ボタン（編集後）

**依存関係**:
- Unit 3 (Calendar API): 更新処理
- Unit 4 (状態復元): 復元処理

### 6. Progress Indicator Component
**責任**: ローディングとプログレスの表示

**主要機能**:
- 保存中のローディング表示
- 復元中のプログレスバー
- データ取得中のローディング表示

### 7. Error Message Component
**責任**: エラーメッセージの表示

**主要機能**:
- エラーメッセージの表示
- リトライボタン
- エラーの種類に応じた適切なメッセージ

### 8. Authentication UI Component
**責任**: 認証状態の表示と認証フロー

**主要機能**:
- 未認証時の認証ボタン表示
- 認証中のローディング表示
- 認証エラーの表示

**依存関係**:
- Unit 1 (認証): 認証状態と認証処理

## 技術スタック
- **言語**: TypeScript
- **UIフレームワーク**: 
  - オプション1: バニラJavaScript + HTML/CSS
  - オプション2: React（軽量版）
  - オプション3: Vue.js（軽量版）
- **スタイリング**: CSS（またはCSS-in-JS）
- **API**: 
  - Chrome Side Panel API
  - Chrome Storage API（UI状態の保存）

## UI/UX設計原則
- **シンプルさ**: ブックマーク作成と同等の手軽さ
- **視覚的フィードバック**: すべての操作に明確なフィードバック
- **エラー処理**: ユーザーフレンドリーなエラーメッセージ
- **アクセシビリティ**: キーボード操作、スクリーンリーダー対応

## レスポンシブデザイン
- サイドパネルのサイズに応じて適切に表示
- 最小幅: 300px
- 最大幅: 600px（推奨）

## アクセシビリティ要件
- **キーボード操作**: すべての主要機能をキーボードのみで操作可能
- **ARIAラベル**: 適切なARIAラベルを設定
- **色のコントラスト**: WCAG 2.1 Level AA基準に準拠（コントラスト比4.5:1以上）

## エラーハンドリング
- **ネットワークエラー**: 「ネットワークエラーが発生しました。再試行してください。」
- **認証エラー**: 「認証に失敗しました。もう一度お試しください。」
- **APIエラー**: 「保存に失敗しました。しばらくしてから再度お試しください。」
- **バリデーションエラー**: 入力フィールドの下にエラーメッセージを表示

## テスト戦略
- **ユニットテスト**: 
  - 各UIコンポーネントのテスト
  - フォームバリデーションのテスト
- **統合テスト**: 
  - 実際のChrome環境でのUIテスト
  - ユーザーフローのテスト
- **E2Eテスト**: 
  - Playwrightを使用したE2Eテスト（将来の拡張）

## 依存関係
- **外部依存**: 
  - Chrome Side Panel API
  - Chrome Storage API
- **内部依存**: 
  - Unit 1 (認証): 認証状態の表示
  - Unit 2 (タブキャプチャ): タブ一覧の表示
  - Unit 3 (Calendar API): 保存・一覧表示・編集
  - Unit 4 (状態復元): 復元ボタンとプログレス

## 他のUnitsとのインターフェース
- **すべてのUnits**: UIを提供し、ユーザー操作を各Unitに伝達

## 実装の優先順位
**優先度**: 高（ユーザー体験の要）
