# ADR-004: Chrome Identity APIの使用（OAuth 2.0）

## ステータス
承認済み

## コンテキスト
GoogleアカウントのOAuth 2.0認証を実装する際、認証方法を選択する必要がありました。

Chrome拡張機能では、OAuth 2.0認証を実装する方法が複数あります：
1. Chrome Identity APIを使用
2. 手動でOAuth 2.0フローを実装
3. サードパーティライブラリを使用

## 決定
Chrome Identity APIを使用してOAuth 2.0認証を実装します。

`chrome.identity.getAuthToken()`を使用して、Googleアカウントの認証トークンを取得します。

## 結果

### ポジティブ
- **簡素化**: OAuth 2.0フローが簡素化される
- **セキュリティ**: Chromeが提供するセキュアな認証フロー
- **ユーザー体験**: ユーザーが既にログインしている場合、シームレスな認証
- **メンテナンス**: ChromeがOAuth 2.0フローを管理するため、メンテナンスが不要
- **標準準拠**: Chrome拡張機能の標準的な認証方法

### ネガティブ
- **Chrome依存**: Chrome拡張機能専用のAPIのため、他のブラウザでは使用不可
- **制約**: Chrome Identity APIの制約に従う必要がある
- **カスタマイズ性**: OAuth 2.0フローの詳細なカスタマイズが困難

### 検討した代替案

#### 代替案1: 手動でOAuth 2.0フローを実装
- **説明**: OAuth 2.0の認証コードフローを手動で実装
- **却下理由**: 実装が複雑、セキュリティリスクが高い、メンテナンスコストが高い

#### 代替案2: サードパーティライブラリを使用
- **説明**: OAuth 2.0ライブラリ（例: `google-auth-library`）を使用
- **却下理由**: Chrome拡張機能のCSP制約により、外部ライブラリの使用が困難、Chrome Identity APIの方が簡潔

#### 代替案3: サーバーサイド認証
- **説明**: サーバーサイドでOAuth 2.0認証を行い、トークンをクライアントに配布
- **却下理由**: サーバーサイドのインフラが必要、コストが高い、このプロジェクトの要件に過剰
