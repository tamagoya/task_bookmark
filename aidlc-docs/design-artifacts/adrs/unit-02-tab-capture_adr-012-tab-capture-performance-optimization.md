# ADR-012: タブ情報取得のパフォーマンス最適化

## ステータス
承認済み

## コンテキスト
Unit 2（タブ状態キャプチャ）では、パフォーマンス要件として「最大20タブの取得を500ms以内で完了する必要がある」（NFR-001）があります。

Chrome Tabs APIには以下のメソッドがあります：
- `chrome.tabs.query()`: 条件に一致するタブを一括取得
- `chrome.tabs.get()`: 特定のタブを個別に取得
- `chrome.tabs.getAllInWindow()`: ウィンドウ内のすべてのタブを取得（**非推奨**）

大量のタブがある場合、個別に`chrome.tabs.get()`を呼び出すと、パフォーマンス要件を満たせない可能性があります。

**`chrome.tabs.getAllInWindow()`を使わない理由**:
1. **非推奨API**: `chrome.tabs.getAllInWindow()`は非推奨（deprecated）であり、将来的に削除される可能性がある
2. **Manifest V3との整合性**: Manifest V3では`chrome.tabs.query()`が推奨されており、より安全で将来性がある
3. **柔軟性**: `chrome.tabs.query({ currentWindow: true })`は`getAllInWindow()`と同等の機能を提供しつつ、より柔軟なクエリ条件を指定できる
4. **互換性**: `chrome.tabs.query()`はより広くサポートされており、ブラウザ間の互換性が高い

## 決定
タブ情報取得のパフォーマンス最適化として、以下の戦略を採用します：

1. **一括取得APIの活用**: `chrome.tabs.query()`を使用して、すべてのタブを一度に取得
   - 個別の`chrome.tabs.get()`呼び出しを避ける
   - ネットワークラウンドトリップを最小化

2. **並列処理の活用**: 取得したタブ情報を並列に`TabInfo`に変換
   - `Promise.all()`を使用して並列処理
   - ただし、`chrome.tabs.query()`が既に一括取得するため、並列処理の効果は限定的

3. **キャッシュの最小化**: タブ情報のキャッシュは最小限に
   - 取得直後の情報のみをキャッシュ（メモリ使用量を抑制）
   - タブが変更された場合、キャッシュを無効化
   - 現時点では、パフォーマンス要件（500ms以内）を満たすため、積極的なキャッシュは不要

4. **遅延読み込み**: ファビコンURLの取得は必要に応じて遅延読み込み
   - 初期表示時はファビコンURLが不要な場合もある
   - 必要になった時点で取得

## 結果

### ポジティブ
- **パフォーマンス要件の達成**: 一括取得APIにより、500ms以内の要件を満たせる
- **ネットワーク効率**: 個別のAPI呼び出しを避けることで、ネットワークラウンドトリップを最小化
- **メモリ効率**: キャッシュを最小限にすることで、メモリ使用量を抑制
- **シンプルな実装**: 一括取得APIを使用することで、実装がシンプルになる

### ネガティブ
- **キャッシュの制限**: 積極的なキャッシュを行わないため、毎回API呼び出しが必要
- **並列処理の効果**: `chrome.tabs.query()`が既に一括取得するため、並列処理の効果は限定的

### 検討した代替案

#### 代替案1: 個別のAPI呼び出し
- **説明**: 各タブに対して`chrome.tabs.get()`を個別に呼び出す
- **却下理由**: パフォーマンス要件（500ms以内）を満たせない可能性が高い、ネットワークラウンドトリップが増加

#### 代替案2: 積極的なキャッシュ
- **説明**: タブ情報を積極的にキャッシュし、変更を監視（`chrome.tabs.onUpdated`など）
- **却下理由**: メモリ使用量の増加、実装の複雑化、現時点では不要（パフォーマンス要件を満たせる）

#### 代替案3: `chrome.tabs.getAllInWindow()`の使用
- **説明**: `chrome.tabs.getAllInWindow()`を使用してウィンドウ内のタブを取得
- **Pros**: シンプル、ウィンドウ内のタブを直接取得できる
- **Cons**: 非推奨APIのため、将来的に削除される可能性がある、Manifest V3との整合性の問題、柔軟性が低い
- **却下理由**: 非推奨APIを採用すると、将来のブラウザアップデートでの削除や非互換性のリスクがある。`chrome.tabs.query({ currentWindow: true })`が同等の機能を提供し、より安全で柔軟。

#### 代替案4: 段階的な取得
- **説明**: 大量のタブ（20個以上）がある場合、段階的に取得
- **却下理由**: 実装の複雑化、パフォーマンス要件（500ms以内）を満たすためには不要、`chrome.tabs.query()`で一括取得可能
