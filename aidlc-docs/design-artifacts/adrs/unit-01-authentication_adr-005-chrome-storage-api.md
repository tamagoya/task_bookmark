# ADR-005: Chrome Storage APIの使用（永続化）

## ステータス
承認済み

## コンテキスト
認証状態を永続化する際、ストレージ方法を選択する必要がありました。

Chrome拡張機能では、以下のストレージオプションがあります：
1. `chrome.storage.local` - ローカルストレージ（10MBまで）
2. `chrome.storage.sync` - 同期ストレージ（100KBまで、複数デバイス間で同期）
3. `localStorage` / `sessionStorage` - Web Storage API
4. IndexedDB - より高度なストレージ

## 決定
認証状態の永続化に`chrome.storage.local`を使用します。

理由：
- 認証トークンは機密情報のため、ローカルに保存（同期しない）
- 10MBの容量で十分
- Chrome Storage APIは暗号化機能を提供

## 結果

### ポジティブ
- **セキュリティ**: ローカルに保存され、他のデバイスと同期されない
- **容量**: 10MBの容量で十分
- **暗号化**: Chrome Storage APIの暗号化機能を利用可能
- **非同期API**: 非同期APIにより、UIのブロックを回避
- **イベント**: ストレージ変更のイベントを監視可能

### ネガティブ
- **容量制限**: 10MBの制限（認証状態には十分だが、将来の拡張には制限）
- **Chrome依存**: Chrome拡張機能専用のAPI
- **同期不可**: 複数デバイス間で同期されない（セキュリティのため、これは意図的）

### 検討した代替案

#### 代替案1: `chrome.storage.sync`を使用
- **説明**: 複数デバイス間で認証状態を同期
- **却下理由**: セキュリティリスク（認証トークンを複数デバイスで同期）、容量制限（100KB）

#### 代替案2: `localStorage`を使用
- **説明**: Web Storage APIの`localStorage`を使用
- **却下理由**: 同期APIのため、UIのブロックの可能性、Chrome Storage APIの方が推奨

#### 代替案3: IndexedDBを使用
- **説明**: より高度なストレージAPIを使用
- **却下理由**: 認証状態の保存には過剰、複雑性が高い
