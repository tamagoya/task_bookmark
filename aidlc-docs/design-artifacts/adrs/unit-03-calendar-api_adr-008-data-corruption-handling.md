# ADR-008: データ破損への対応と堅牢性設計

## ステータス
承認済み

## コンテキスト
GoogleカレンダーのWebUIやその他カレンダーツールによって、保存されているデータが書き換えられる可能性があります。そのため、以下の要件を満たす必要があります：

1. **部分的な読み込み**: データが部分的に破損している場合でも、読み込める部分は表示する
2. **破損データの識別**: データが破損している場合、明確に識別できる
3. **エラー情報の提示**: どのフィールドが破損しているかをユーザーに提示する
4. **最小限の必須フィールド**: `eventId`と`title`が有効であれば、部分的にでも読み込み可能

## 決定
データ破損への対応と堅牢性設計を採用します：

1. **ValidationError Value Object**: データ検証エラーの詳細を記録
   - `field`: 破損したフィールド名
   - `errorCode`: エラーコード（例: "INVALID_JSON", "MISSING_FIELD"）
   - `errorMessage`: ユーザー向けのエラーメッセージ
   - `severity`: エラーの深刻度（'CRITICAL' | 'WARNING' | 'INFO'）
   - `recoverable`: 部分的に読み込み可能かどうか

2. **WorkStateの拡張**: 破損データの状態を保持
   - `isCorrupted: boolean`: データが破損しているかどうかのフラグ
   - `validationErrors: ValidationError[]`: 検証エラーのリスト
   - `markAsCorrupted()`: データの破損をマーク
   - `getCorruptedFields()`: 破損しているフィールドのリストを取得
   - `canPartiallyLoad()`: 部分的に読み込み可能かどうかを判定

3. **段階的な検証**: JSON形式 → スキーマバージョン → 必須フィールド → オプションフィールドの順で検証

4. **部分的な読み込み**: 各段階でエラーが発生しても、それまでのデータは保持

5. **TaskBookmarkCorrupted Domain Event**: データ破損が検出された時に発行

6. **EventDescription.tryParse()**: 堅牢性を重視したJSON解析（部分的に読み込み可能な場合）

## 結果

### ポジティブ
- **堅牢性**: データが部分的に破損していても、読み込める部分は表示できる
- **ユーザー体験**: 完全に読み込めない場合でも、部分的にでも情報を表示できる
- **エラー情報**: どのフィールドが破損しているかを明確に提示できる
- **修復の可能性**: 部分的に読み込めたデータは、ユーザーが手動で修復できる（将来的な拡張）
- **監視**: データ破損の発生を監視できる（Domain Event）

### ネガティブ
- **複雑性の増加**: 破損データの処理ロジックにより、コードの複雑性が増加
- **パフォーマンス**: 段階的な検証により、読み込み時間が延長される可能性
- **テストの複雑性**: 様々な破損パターンをテストする必要がある
- **UIの複雑性**: 破損データを視覚的に区別し、エラー詳細を表示する必要がある

### 検討した代替案

#### 代替案1: 破損データを完全に拒否
- **説明**: データが破損している場合、完全に読み込みを拒否
- **却下理由**: ユーザー体験が悪化、部分的にでも読み込める情報が失われる

#### 代替案2: 自動修復
- **説明**: データが破損している場合、自動的に修復を試みる
- **却下理由**: 誤った修復により、データがさらに破損する可能性がある、ユーザーの意図を推測できない

#### 代替案3: サーバーサイドでの検証
- **説明**: サーバーサイドでデータの検証と修復を実行
- **却下理由**: このプロジェクトはChrome拡張機能のみで、サーバーサイドを持たない

#### 代替案4: 読み取り専用のカレンダー
- **説明**: 読み取り専用のカレンダーを作成し、書き込みを禁止
- **却下理由**: ユーザーがGoogleカレンダーのWebUIで編集できない、柔軟性が失われる
