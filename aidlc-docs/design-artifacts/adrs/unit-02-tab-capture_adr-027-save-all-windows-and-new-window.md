# ADR-027: 保存対象を全ウィンドウとし、保存後に新規ウィンドウを1タブで表示する

## ステータス
承認済み

## コンテキスト
ユーザーは複数のChromeウィンドウにまたがって仕事をすることが多く、従来の「現在のウィンドウのタブのみ」を保存する仕様では、一括で仕事状態を保存できないという課題がありました。また、保存後にタブを閉じただけでは、すぐにタスクブックマークを開いて別の仕事に移りづらいというフィードバックがありました。

## 決定
以下の仕様に変更することを決定しました。

1. **保存対象を「すべてのChromeウィンドウで開いているタブ」とする**
   - タブ一覧の取得・表示も「全ウィンドウ」を対象とする
   - 取得順序は「ウィンドウID昇順・同一ウィンドウ内は index 昇順」で一意に定義する

2. **保存成功後、保存した全タブを閉じる**
   - 保存時に取得したタブのID一覧を保持し、Calendar API への保存が成功した場合にのみ、それらのタブを一括で閉じる
   - 保存失敗時はタブを閉じない

3. **保存成功後、新しいタブを1つだけ開いた新規ウィンドウを表示する**
   - `ChromeWindowsAdapter.createWindow(['about:newtab'])` により、新しいタブを1つだけ開いたウィンドウを開く
   - ユーザーがすぐにタスクブックマークを開いて別の仕事を再開できるようにする

4. **保存成功後、サイドパネルが開いているウィンドウを維持する**（2026-02-13 追記）
   - `chrome.sidePanel.open()` はユーザージェスチャーへの直接応答でのみ呼び出し可能であり、非同期処理（API保存・タブ閉じ）後には呼び出せない。
   - そのため、新規ウィンドウを作ってサイドパネルを開く方式ではなく、**既存のサイドパネル付きウィンドウを維持する方式**を採用する。
   - 具体的には: (1) `chrome.windows.getLastFocused()` でサイドパネルが開いているウィンドウを取得、(2) そのウィンドウに `chrome.tabs.create({ windowId, url: 'about:newtab' })` で新しいタブを先に作成、(3) 保存済みタブを全て閉じる。他のウィンドウはタブが無くなり自動で閉じるが、新しいタブを作ったウィンドウはサイドパネルごと残る。
   - フォールバック: ウィンドウの維持に失敗した場合は、従来どおり `createWindow(['about:newtab'])` で新規ウィンドウを作成する（サイドパネルは開かない）。

## 代替案
- **現在のウィンドウのみ保存を残し、オプションで「全ウィンドウ」を選べるようにする**:  UXの複雑化を避けるため、本リリースでは「常に全ウィンドウ」に統一した
- **保存後に新規ウィンドウを開かず、現在のウィンドウだけを閉じて空白にする**: 複数ウィンドウを閉じた後に「どのウィンドウにフォーカスがあるか」が不明確になるため、新規ウィンドウを明示的に開く方式を採用した

## 結果
- Unit 2 の責任範囲に「全ウィンドウのタブ取得」「保存対象タブの一括閉じ」「新規ウィンドウ作成の利用」が追加される
- `ChromeTabsAdapter.getAllTabs()`、`TabCaptureService.getAllWindowsTabs()`、`TabCaptureService.closeAllCapturedTabs(tabIds)` の追加
- Service Worker の `SAVE_WORK_STATE` ハンドラーで、上記フローを実行する
- ドメインイベント `TabsCaptured` の `windowId` は、全ウィンドウ取得時に `0` とする（複数ウィンドウを表す）
