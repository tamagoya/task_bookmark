# タスクブックマーク Chrome拡張機能 - 動作確認ガイド

## 概要

本ガイドでは、Bolt 1とBolt 2で実装された機能の動作確認手順を説明します。

**実装済み機能**:
- ✅ Googleアカウント認証（OAuth2）
- ✅ カレンダー初期化（専用カレンダーの自動作成）
- ✅ トークン自動リフレッシュ
- ✅ 認証状態の管理

**未実装機能**（今後のBoltで実装予定）:
- ⏳ タブ情報の取得（Bolt 3）
- ⏳ 仕事状態の保存（Bolt 4）
- ⏳ 保存済み仕事一覧表示（Bolt 5）
- ⏳ 仕事状態の復元（Bolt 6）

---

## 前提条件

### 1. OAuth2設定の確認

`manifest.json`にOAuth2クライアントIDが設定されていることを確認してください：

```json
"oauth2": {
  "client_id": "742273768009-d2551p7a54hv181bj5quunq6usj58hlp.apps.googleusercontent.com",
  "scopes": [
    "https://www.googleapis.com/auth/calendar"
  ]
}
```

**注意**: 開発環境で異なる拡張機能IDを使用している場合、OAuth2クライアントIDを再設定する必要があります。詳細は`OAUTH2_SETUP.md`を参照してください。

### 2. Google Calendar APIの有効化

Google Cloud ConsoleでGoogle Calendar APIが有効になっていることを確認してください。

## ステップ2: Chrome拡張機能のインストール

### 2.1 開発者モードの有効化

1. Chromeブラウザで `chrome://extensions/` を開く
2. 右上の「開発者モード」トグルをONにする

### 2.2 拡張機能の読み込み

1. 「パッケージ化されていない拡張機能を読み込む」をクリック
2. `FRONTEND/dist`ディレクトリを選択
3. 拡張機能が一覧に表示されることを確認

### 2.3 拡張機能の確認

- **名前**: タスクブックマーク
- **ID**: 拡張機能IDが表示される（例: `abcdefghijklmnopqrstuvwxyz123456`）
- **バージョン**: 0.1.0
- **エラー**: エラーが表示されていないことを確認

## ステップ3: 基本動作確認

### 3.1 サイドパネルの表示

1. 拡張機能のアイコンをクリック（ツールバーに表示されているはず）
2. サイドパネルが開くことを確認
3. 以下のUI要素が表示されることを確認：
   - タイトル: 「タスクブックマーク」
   - 認証状態: 「認証状態を確認中...」
   - 認証ボタン: 初期状態では非表示

### 3.2 コンソールログの確認

1. サイドパネルを右クリック → 「検証」を選択
2. 「Console」タブを開く
3. エラーメッセージがないことを確認

## ステップ4: 認証機能の確認

### 4.1 認証状態の確認

**期待される動作**:
- サイドパネルを開いた時点で、認証状態が自動的に確認される
- 未認証の場合、「認証する」ボタンが表示される
- 認証済みの場合、「ログアウト」ボタンが表示される

**確認手順**:
1. サイドパネルを開く
2. 認証状態のメッセージを確認
3. 表示されるボタンを確認

### 4.2 認証の実行

**期待される動作**:
1. 「認証する」ボタンをクリック
2. Googleアカウントの認証画面が表示される
3. 認証が完了すると、サイドパネルに認証済み状態が表示される
4. 専用カレンダー（「タスクブックマーク」）が自動作成される

**確認手順**:
1. 「認証する」ボタンをクリック
2. Googleアカウントの認証画面が表示されることを確認
3. 認証を完了（必要に応じてアカウントを選択、権限を許可）
4. サイドパネルに戻り、認証状態が更新されることを確認
5. Googleカレンダー（https://calendar.google.com/）を開き、「タスクブックマーク」という名前のカレンダーが作成されていることを確認

**確認ポイント**:
- ✅ 認証画面が正常に表示される
- ✅ 認証が成功する
- ✅ サイドパネルに認証済み状態が表示される
- ✅ 専用カレンダーが作成される

### 4.3 認証エラーの確認

**想定されるエラー**:

1. **"bad client id"エラー**
   - **原因**: OAuth2クライアントIDが正しく設定されていない、または拡張機能IDと一致していない
   - **対処**: `OAUTH2_SETUP.md`を参照してOAuth2クライアントIDを再設定

2. **"Access blocked"エラー**
   - **原因**: OAuth同意画面でスコープが追加されていない、またはテストユーザーが追加されていない
   - **対処**: Google Cloud ConsoleでOAuth同意画面を確認

3. **"Google Calendar API not enabled"エラー**
   - **原因**: Google Calendar APIが有効になっていない
   - **対処**: Google Cloud ConsoleでGoogle Calendar APIを有効化

### 4.4 ログアウトの確認

**期待される動作**:
1. 「ログアウト」ボタンをクリック
2. 認証状態がクリアされる
3. 「認証する」ボタンが再表示される

**確認手順**:
1. 認証済み状態で「ログアウト」ボタンをクリック
2. 認証状態が「未認証」に戻ることを確認
3. 「認証する」ボタンが表示されることを確認

## ステップ5: カレンダー初期化の確認

### 5.1 専用カレンダーの作成確認

**期待される動作**:
- 初回認証時に、「タスクブックマーク」という名前の専用カレンダーが自動作成される
- 既に同名のカレンダーが存在する場合、既存のカレンダーを使用する

**確認手順**:
1. Googleカレンダー（https://calendar.google.com/）を開く
2. 左側のカレンダー一覧で「タスクブックマーク」という名前のカレンダーを探す
3. カレンダーが存在することを確認
4. カレンダーの色や表示設定を確認（任意）

### 5.2 既存カレンダーの再利用確認

**確認手順**:
1. 一度ログアウトする
2. 再度認証する
3. 新しいカレンダーが作成されず、既存のカレンダーが使用されることを確認

## ステップ6: トークンリフレッシュの確認

### 6.1 自動リフレッシュの確認

**期待される動作**:
- 30分ごとにトークンが自動的にリフレッシュされる
- ユーザーは何も操作する必要がない

**確認手順**:
1. 認証を完了する
2. 30分待つ（または、開発者ツールでアラームを手動でトリガー）
3. コンソールログでトークンリフレッシュのログを確認

**注意**: 実際に30分待つのは現実的ではないため、開発者ツールでアラームを手動でトリガーする方法を推奨します。

### 6.2 アラームの手動トリガー（開発用）

1. `chrome://extensions/` を開く
2. 拡張機能の「詳細」をクリック
3. 「サービスワーカー」のリンクをクリック
4. 開発者ツールの「Console」タブで以下を実行：

```javascript
// アラームを手動でトリガー
chrome.alarms.create('refreshToken', { delayInMinutes: 0 });
```

5. コンソールログでトークンリフレッシュのログを確認

### 7.1 ネットワークエラーの確認

**確認手順**:
1. インターネット接続を一時的に切断
2. 認証を試みる
3. 適切なエラーメッセージが表示されることを確認
4. インターネット接続を復元
5. 再度認証を試み、正常に動作することを確認

### 7.2 権限エラーの確認

**確認手順**:
1. Google Cloud ConsoleでGoogle Calendar APIを一時的に無効化
2. 認証を試みる
3. 適切なエラーメッセージが表示されることを確認
4. Google Calendar APIを再有効化
5. 再度認証を試み、正常に動作することを確認

## ステップ8: ストレージの確認

### 8.1 Chrome Storageへの保存確認

**確認手順**:
1. 認証を完了する
2. `chrome://extensions/` を開く
3. 拡張機能の「詳細」をクリック
4. 「ストレージ」セクションを確認
5. 以下のデータが保存されていることを確認：
   - `authState`: 認証状態（アクセストークン、リフレッシュトークン、カレンダーIDなど）

### 8.2 ストレージのクリア確認

**確認手順**:
1. 認証を完了する
2. 「ストレージ」セクションで「クリア」をクリック
3. サイドパネルを再読み込み
4. 認証状態が「未認証」に戻ることを確認

## ステップ9: 開発者ツールでの確認

### 9.1 Service Workerの確認

1. `chrome://extensions/` を開く
2. 拡張機能の「詳細」をクリック
3. 「サービスワーカー」のリンクをクリック
4. 開発者ツールが開き、Service Workerのログを確認できる

### 9.2 コンソールログの確認

**確認すべきログ**:
- 拡張機能のインストール時のログ
- 認証処理のログ
- カレンダー初期化のログ
- トークンリフレッシュのログ
- エラーログ（発生した場合）

### 9.3 ネットワークリクエストの確認

1. Service Workerの開発者ツールで「Network」タブを開く
2. 認証を実行
3. 以下のAPIリクエストが送信されることを確認：
   - `https://www.googleapis.com/oauth2/v2/userinfo`（認証情報取得）
   - `https://www.googleapis.com/calendar/v3/calendars`（カレンダー一覧取得）
   - `https://www.googleapis.com/calendar/v3/calendars`（カレンダー作成、必要に応じて）

## トラブルシューティング

### 問題1: サイドパネルが開かない

**原因**:
- 拡張機能が正しくインストールされていない
- Service Workerにエラーがある

**対処**:
1. `chrome://extensions/` で拡張機能のエラーを確認
2. Service Workerのログを確認
3. 拡張機能を再読み込み

### 問題2: 認証ボタンが表示されない

**原因**:
- JavaScriptエラーが発生している
- メッセージハンドラーが正しく動作していない

**対処**:
1. サイドパネルの開発者ツールでコンソールエラーを確認
2. Service Workerのログを確認
3. `sidepanel.ts`のコードを確認

### 問題3: 認証が失敗する

**原因**:
- OAuth2クライアントIDが正しく設定されていない
- Google Calendar APIが有効になっていない
- テストユーザーが追加されていない（テストモードの場合）

**対処**:
1. `OAUTH2_SETUP.md`を参照してOAuth2設定を確認
2. Google Cloud ConsoleでAPIの有効化を確認
3. OAuth同意画面でテストユーザーを確認

### 問題4: カレンダーが作成されない

**原因**:
- 認証が完了していない
- Google Calendar APIの権限がない
- APIリクエストが失敗している

**対処**:
1. 認証状態を確認
2. Service Workerのログでエラーを確認
3. ネットワークリクエストのレスポンスを確認
